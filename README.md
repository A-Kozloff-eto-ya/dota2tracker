# Dota2Tracker

Тёмное SPA на React 19 + Vite + TypeScript для расчёта **персонального рейтинга** игроков
Dota 2 по данным [STRATZ](https://stratz.com) и сборки **равносильных (сбалансированных)
команд**.

## Возможности

- **Единственный источник данных — STRATZ API**: поиск игроков, статистика, герои,
  behavior score и свежий ранк через GraphQL.
- **Трекинг игроков** — поиск по нику (STRATZ GraphQL `search`), добавление по
  `account_id`, `SteamID64`, `SteamID3` или ссылке на профиль.
- **Формула рейтинга** (двузначная шкала 1–100):

  ```
  Rating = (wTier·Tier + wPerf·Perf + wAct·Activity) / Σw
  ```

  - `Tier` — публичная медаль (`rank_tier`) и бонус лидерборда из STRATZ.
  - `Perf` — KDA, GPM, XPM, урон в минуту и винрейт последних N матчей.
  - `Activity` — общий винрейт (с поправкой на объём выборки) и пул героев.
  - Веса и пороги редактируются на вкладке «Формула» с мгновенным пересчётом.
  - **Ручные оценки калибруют шкалу**: значение, введённое в ячейке таблицы,
    главнее авторасчёта, а авторасчёты остальных игроков пересчитываются
    относительно ручных (общая к общей, каждая позиция к своей) — кусочно-линейная
    калибровка, чтобы формула и ручные значения жили в одной шкале.
- **Балансировка команд** — деление пула на 2–4 команды с равными средними рейтингами:
  точный перебор для 2 команд (до 18 игроков), снейк-драфт + локальная оптимизация для
  остальных случаев; опциональный учёт позиций 1–5; drag-and-drop для ручной подстройки.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # проверка типов + прод-сборка
npm run lint
```

## Данные и приватность

- **STRATZ API — единственный источник данных**: винрейт, матчи, герои, behavior score
  и свежий ранг через GraphQL `player(steamAccountId)`.
- Steam и STRATZ вызываются через серверные Vercel Functions. Их ключи задаются как
  `STEAM_API_KEY` и `STRATZ_API_KEY` и не попадают в браузерный bundle.
- Список героев (названия, картинки) берётся из констант STRATZ
  (`constants { heroes { … } }`) и кэшируется на неделю.
- При настройке Supabase список общего пула и пользователи хранятся в PostgreSQL.
  Локальный режим без переменных Supabase сохраняется для разработки интерфейса.
- Точный MMR скрыт Valve, поэтому рейтинг — локальная формула над публичными метриками.

## Supabase и Vercel

1. Создайте бесплатный проект Supabase.
2. Выполните SQL из `supabase/schema.sql` в SQL Editor.
3. Включите Email provider и magic link в Supabase Auth.
4. Настройте **Authentication → URL Configuration** — без этого переход по
   ссылке из письма будет отклоняться:

   - **Site URL** — боевой адрес приложения (например, `https://<app>.vercel.app`);
   - **Redirect URLs** — все адреса, с которых запускается вход:
     `https://<app>.vercel.app/**`, `https://*.vercel.app/**` (превью-деплои)
     и `http://localhost:5173/**` для локальной разработки.

   Приложение отправляет ссылку на `window.location.origin`, поэтому текущий
   адрес сайта обязан попасть в этот список. Иначе после клика по ссылке
   Supabase вернёт ошибку (`Redirect URL not allowed`), а приложение покажет
   её всплывающим уведомлением.
5. Скопируйте `.env.example` в `.env.local` для локальной разработки.
6. Добавьте все переменные из `.env.example` в Vercel Project Settings.
7. Запускайте Vercel Functions локально через `vercel dev`, если нужны `/api/*`.

Первый пользователь, зарегистрированный после применения схемы, автоматически получает
роль администратора. В админ-панели он сможет назначать администраторов другим пользователям.

**Особенность magic link (PKCE):** ссылка из письма подтверждает вход в том же
браузере, где был запрос (`code_verifier` хранится в localStorage). Открыть
письмо на телефоне и залогиниться на компьютере так нельзя — запросите ссылку
заново в нужном браузере.
